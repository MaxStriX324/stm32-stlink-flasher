# STM32 ST-Link Flasher

**Портфолио:** [описание инструмента и проекты автора](https://maxstrix324.github.io/project/stm32-stlink-flasher/). Ниже приведены актуальные возможности, ограничения и инструкции этого репозитория.

Графическая программа для прошивки **STM32F103 / STM32F405** через ST-Link на Windows 10/11 (x64). Запись и последующая проверка Flash выполняются через OpenOCD (предпочтительно) либо уже установленный STM32CubeProgrammer.

**Ни Python, ни VS Code, ни PlatformIO на компьютере прошивки не требуются.** Для GUI достаточно встроенного Windows PowerShell 5.1.

## Установка: один раз запустить install.bat

1. Нажмите **Code → Download ZIP** и распакуйте репозиторий.
2. Двойным щелчком запустите **install.bat**.
3. Установщик копирует файлы в `%LOCALAPPDATA%\Programs\STM32-STLink-Flasher` и ищет установленный OpenOCD (например, из PlatformIO). Если OpenOCD отсутствует, но установлен STM32CubeProgrammer, он будет использован. Если оба отсутствуют, установщик автоматически скачивает портативный Windows x64 ZIP xPack OpenOCD с GitHub, проверяет SHA-256 по закреплённому значению из официального релиза и распаковывает его.
4. Создаётся ярлык **STM32 ST-Link Flasher** на рабочем столе, после чего программа открывается автоматически.

**Повторное выполнение install.bat** обновляет программу, сохраняя `settings.json` и предыдущие журналы. Обычная установка не запрашивает права администратора.

Если интернет или GitHub недоступен, можно вручную получить Windows ZIP на [странице выпусков xPack OpenOCD](https://github.com/xpack-dev-tools/openocd-xpack/releases) и распаковать в папку `tools\openocd` внутри каталога установленного приложения. После этого повторно запустите `install.bat`.

Для работы ST-Link должен быть установлен корректный USB-драйвер. На ПК, где ST-Link уже успешно работает из PlatformIO, драйвер обычно установлен. При необходимости используйте [официальный STSW-LINK009](https://www.st.com/en/development-tools/stsw-link009.html).

## Работа с программой

В окне две основные кнопки:

- **1. ПРОВЕРИТЬ ПОДКЛЮЧЕНИЕ.** Программа подключается к ST-Link и читает Device ID. Ручной выбор STM32F103 или STM32F405 не нужен. Совпадение Device ID с ожидаемой группой не доказывает точную маркировку MCU.
- **2. ПРОШИТЬ С ПРОВЕРКОЙ.** Сначала выберите `firmware.bin` кнопкой «Выбрать BIN». Нажмите «Прошить с проверкой», проверьте адрес файла, размер, SHA-256 и обнаруженный MCU, затем подтвердите запись. Программа **ещё раз проверяет MCU** перед записью, прошивает по адресу `0x08000000` и выполняет verify.

Во время операции отображается индикатор активности, ниже — журнал. Полные журналы сохраняются в каталоге `logs`. Это **не процент записи**, а индикатор выполняющейся операции.

### Где найти firmware.bin после сборки PlatformIO

В VS Code нажмите **PlatformIO: Build**. Готовый бинарный файл обычно находится здесь:

```text
проект/
└── .pio/
    └── build/
        └── ИМЯ_ОКРУЖЕНИЯ/
            └── firmware.bin
```

Имя окружения — часть секции `[env:...]` в файле `platformio.ini`. BIN выбирается непосредственно из этой папки — копировать его в программу необязательно.

### Подключение платы

Подключите ST-Link через **SWDIO, SWCLK, GND** и правильное питание целевого MCU. **NRST** желательно предусмотреть. Если два устройства подают питание, предварительно проверьте схему.

**Перед прошивкой силового контроллера обязательно отключите высоковольтную часть, двигатель, цепи управления ключами и исполнительные устройства.**

## Что проверяется

- Подключение ST-Link и считывание Device ID.
- Допустимая группа STM32: для STM32F103 — `0x410/0x412/0x414/0x430`, для STM32F405 — `0x413`. Обозначения не всегда уникальны среди родственных микроконтроллеров.
- Расширение BIN, ненулевой размер, векторы начального стека и reset handler для образа с базовым адресом `0x08000000`.
- Повторная проверка MCU непосредственно перед записью.
- Проверка Flash после программирования по результату OpenOCD или STM32CubeProgrammer.

В **обычном firmware.bin нет заголовка с названием процессора или аппаратной ревизией**. Поэтому программа не может определить, соответствует ли выбранный файл именно вашей печатной плате. Проверяйте окружение сборки PlatformIO.

Поддерживаются только прошивки для внутренней Flash, начинающиеся с `0x08000000`. Собственные загрузчики, смещение адреса и изменение option bytes не поддерживаются. Программа не выполняет снятие защиты чтения. Проверка Flash не заменяет функциональных испытаний.

## Исправление ошибки определения MCU (ноябрь 2026)

Если в журнале есть строки `STLINK V2J38S7`, `Target voltage: 3.29` и `Cortex-M4 processor detected`, то ST-Link уже подключился. Прежняя ошибка `OpenOCD could not read the MCU Device ID` была связана с тем, что команда `mdw` не выводила данные в лог при запуске OpenOCD через `-c`. Сейчас идентификатор читается через `read_memory` и явно печатается как `STM32_IDCODE=0x...`. Вывод stdout и stderr читается раздельно, без появления `NativeCommandError` в обычном логе.

**Как обновить установленную программу:** скачайте свежий ZIP репозитория, распакуйте и снова запустите `install.bat`. Установщик обновит скрипты в `%LOCALAPPDATA%\Programs\STM32-STLink-Flasher` и сохранит настройки. После обновления откройте ярлык на рабочем столе, нажмите «Проверить подключение». В журнале должна появиться строка `DETECTED_TARGET=STM32F405;DEVICE_ID=0x413` (для совместимого STM32F405) или соответствующая строка для STM32F103. **Не начинайте прошивку, пока проверка подключения не завершится успешно.**

Для проверки парсера без программатора выполните в распакованном репозитории `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\check.ps1`. Этот тест проверяет синтаксис и разбирает искусственные примеры идентификаторов; он не заменяет проверку с физическим ST-Link.

## Настройки и диагностика

`settings.json` позволяет настроить `openocd_path`, `cube_cli_path`, `swd_frequency_khz`, `auto_reset_after_verify`, `stlink_serial`, `connect_under_reset`.

Если ST-Link не определяется, проверьте драйвер, проводку и питание MCU. При необходимости снизьте `swd_frequency_khz` до 400. Опции `connect_under_reset` и явный `stlink_serial` пока не реализованы для OpenOCD — их можно использовать с резервным STM32CubeProgrammer.

Если ярлык открывается и сразу закрывается, запустите `GUI.bat` из `%LOCALAPPDATA%\Programs\STM32-STLink-Flasher` — в консоли останется сообщение об ошибке запуска.

Для проверки синтаксиса всех PowerShell-скриптов выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\check.ps1
```

## Обновление программы через Git (update.bat)

После установки запустите **`update.bat`** двойным щелчком. Для Git-копии программа проверит адрес `origin`, отсутствие несохранённых изменений в отслеживаемых файлах, затем выполнит `git fetch` и `git merge --ff-only` основной ветки `main`. Принудительный сброс (`reset --hard`) не применяется. При необходимости Git for Windows устанавливается через `winget` в профиль пользователя; если установка недоступна, утилита сообщит об этом.

**Если проект был скачан через Download ZIP:** `update.bat` не перезаписывает старую папку. Он создаёт отдельный Git-клон `<имя-репозитория>-git` рядом с ней (повторный запуск обновит этот клон), после чего проверяет установку. Для дальнейшей работы используйте новый каталог; свои SVG, DRL, CSV, архивы и локальные настройки перенесите самостоятельно, если они нужны в новой копии. Не перемещайте `.venv`: окружение будет создано заново.

**Если Git сообщает о локальных изменениях** (например, редактировали отслеживаемый `settings.json` или скрипты), обновление остановится, не затирая их. Сохраните отдельную копию конфигурации, затем зафиксируйте, отмените или перенесите изменения через Git и повторите запуск.
- **STM32 Flasher:** `update.bat` можно запускать из установленного `%LOCALAPPDATA%\Programs\STM32-STLink-Flasher`. Он использует отдельный Git-клон в `%LOCALAPPDATA%\Programs\stm32-stlink-flasher-source`, после чего запускает установщик без автоматического открытия GUI. Существующий `settings.json` и журналы установленной программы сохраняются.
